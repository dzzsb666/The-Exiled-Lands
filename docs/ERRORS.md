# 发布错误与规避

## 2026-10-15：把翻译复刻任务做成自行设计的地图

用户明确指出图标和UI没有一比一参照原站，再次确认任务只有翻译成中文，其余完全复刻。已确认：实现采用自行选取的Lucide分类图标、资源圆点、颜色、顶栏和侧栏布局；之前的功能测试通过不能证明满足复刻要求。

原因：原站访问被站点安全策略阻止、原始样式和图标素材缺失时，仍继续以通用图标和自行设计补齐。缺少参考证据本应明确报告，不能当成设计授权。

纠正：新增根目录 `AGENTS.md` 固定用户约束，`design-qa.md` 明确标为blocked并列出素材缺项和已知偏离。在取得足够原站证据前，不继续猜测图标、CSS、地图素材或交互，也不把现有程序称为复刻完成。原站素材和关键状态齐备后逐项替换，再同视口对照验收。

## 2026-10-14：静态部署遗漏构建文件

已确认症状：更新发布的文件清单只有 `vercel.json`，Vercel仍返回READY并分配生产域名，导致网站短暂缺少首页。已确认直接原因：未在创建部署之前验证清单包含首页与应用资源。

触发条件：在持久JavaScript会话中跨调用重置数组并复用此前创建的递归函数；实际输出新数组未包含构建文件。闭包绑定/执行环境处理可能参与了问题，但未单独验证运行环境内部机制，不将其记为已确定语言行为。

修复：在同一次调用中重新创建数组和递归函数，核验完整8项文件清单，补传变化文件，再用完整清单重新发布。最终部署 `dpl_6rV5STKkV7P8U76x8zg9xVrE8WW1` 返回READY，线上页面已加载修正版JS与2812个点位。

预防：新增无状态脚本 `scripts/prepare-static-deploy.mjs`；缺少首页、HTML引用的JS/CSS、地图、点位JSON或核对CSV时直接抛错。后续发布前先读取本记录；上传可复用已有文件，但创建部署必须提交全部文件引用，并检查真实线上页面，而非只查看READY。
